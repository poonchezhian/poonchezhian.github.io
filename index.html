Connect to an EC2 server over SSM without opening port 22

3 min readPermalink

You have an EC2 server. You want a terminal on it. Somebody, wisely, closed port 22. This is the situation SSMConnect was built for: you still get PuTTY, WinSCP, MobaXterm or Remote Desktop, and the server keeps every inbound port closed.

Why port 22 is closed, and why that is good

An open SSH port is reachable by the whole internet, and it is attacked all day long. Many teams close it and use AWS Systems Manager (SSM) Session Manager instead. The server's SSM Agent calls out to AWS, and AWS carries your connection back over that existing channel. No inbound port, no bastion host, no VPN.

The catch is that the usual way to use it is a long command line, plus a plugin, plus a port number you have to remember. If you are a developer who just wants to log in, that is a lot of plumbing. If you want to understand it first, read SSM port forwarding explained.

What SSMConnect does for you

SSMConnect is a free Windows app (and a Linux app) that does the plumbing:

  1. Finds your servers. Sign in once with your company sign-in and it lists the running servers in every AWS account under it, and marks which ones SSM can reach.
  2. Opens one tunnel per server. Each server gets its own local port on 127.0.0.1. The tunnels run as you, not as an administrator, and restart by themselves if they drop.
  3. Sets up your tools. Linux servers get saved sessions called SSC - <server name> in PuTTY, WinSCP and MobaXterm. Windows servers open in Remote Desktop.
  4. Tells you the truth about the connection. A server card turns green only when its tunnel is really up. If something is wrong, the card says what, in plain words.

Your first connection in five steps

  1. Download SSMConnect for Windows and run the installer. It adds the AWS CLI and the Session Manager plugin if they are missing.
  2. In the setup wizard, paste your company sign-in address and sign in once in the browser.
  3. Tick the servers you want.
  4. Point each Linux server at its key file. Find key files on this PC does most of the work.
  5. Save. The tunnels start, and the dashboard shows your servers.

From then on, open PuTTY, WinSCP or MobaXterm and pick the session called SSC - your server name, or click PuTTY, WinSCP or Remote Desktop on the server's card.

What you need on the AWS side

SSMConnect cannot give a server something it does not have. For a server to be reachable, it needs the SSM Agent running and an instance role such as AmazonSSMManagedInstanceCore. Your own AWS role needs ec2:DescribeInstances, ssm:DescribeInstanceInformation and ssm:StartSession. If a server shows up as not reachable, For IT teams lists exactly what to ask for.

Production servers are marked

SSMConnect reads the Environment tag and shows a red PROD label on production servers, so you notice before you type a command. Server types and tags explains how to get the labels right.

When something does not work

The most common problems have a plain fix: an expired sign-in (one click on Sign in), a missing key, or a server that is not yet registered with SSM. Troubleshooting walks through each.

Once you are connected: copy files between servers

SSMConnect has one more trick. Once two servers are connected, Servers > File transfer opens two panes so you can copy files from one server to the other, again with port 22 closed. It is an extra on top of connecting, and it has its own write-up: How to copy files between EC2 servers when port 22 is closed.

SSMConnect is an early release, so try it on a non-production server first.

Questions people ask

What is SSMConnect?

SSMConnect is a free, open-source desktop app for Windows and Linux. It finds your EC2 servers, opens secure tunnels through AWS Systems Manager Session Manager, and makes each server one click away. On Windows it sets up PuTTY, WinSCP, MobaXterm and Remote Desktop. On Linux it gives every server a short ssh name and opens your terminal, file manager and Remote Desktop client.

Do I need to open port 22 or give my server a public IP?

No. The tunnel runs through AWS Systems Manager, so the server needs no inbound SSH or RDP rule and no public address. The server does need the SSM Agent running, an IAM instance profile that allows Systems Manager, and outbound HTTPS to the Systems Manager endpoints.

Does it work with PuTTY, WinSCP and MobaXterm?

Yes, on Windows. SSMConnect saves a ready-to-use session for each server in the tools you have installed. It keeps a backup of the files it edits and leaves your own saved sessions alone.

Does the Linux version have a window with a Connect button?

Yes. The Linux edition is a native desktop app with the same dashboard as Windows: a card for each server with a live status, Connect, Terminal, Files and Remote Desktop buttons, and Start, Stop and Restart for all connections. It also works from any terminal, because every server gets a short name such as ssh ssc-web-prod, so scp, rsync and VS Code Remote-SSH work too.

How do I install it on Linux, and is the download signed?

Download the .bin installer and run it, or install the .rpm (Fedora, RHEL 10 and clones, openSUSE) or the .deb (Debian 13, Ubuntu 24.04, Mint 22). The .rpm and .deb also add a signed update repository, so new versions arrive with dnf upgrade or apt upgrade. Every Linux download has an OpenPGP signature that you can check against the published key fingerprint.

Can I reach Windows servers with Remote Desktop?

Yes. SSMConnect opens a tunnel to the server&#x27;s Remote Desktop port and launches the Remote Desktop client (Remmina or FreeRDP on Linux). A Windows password you copy stays on the clipboard for 60 seconds and is then cleared.

How do I sign in to AWS?

Use your company sign-in page (AWS IAM Identity Center, also called AWS SSO) with one click, or use access keys. If your browser has to sign in, SSMConnect opens it for you.

Is SSMConnect safe to use?

Tunnels listen on 127.0.0.1 only, so other computers on your network cannot reach them. Every value passed to the AWS CLI is validated, no password or key is stored, nothing runs as administrator, and updates are checked against a published SHA-256 checksum. The Windows installer is not code-signed yet, so Windows SmartScreen may show a warning the first time. Linux downloads carry OpenPGP signatures.

Does it replace the AWS CLI?

No. SSMConnect uses the AWS CLI and the Session Manager plugin underneath and installs them for you if they are missing. It saves you from typing the commands and remembering the ports.

Which systems does it run on?

Windows 10 or later (64-bit), and 64-bit Linux desktops with GTK 4.12 and libadwaita 1.5 or newer, such as Ubuntu 24.04, Fedora 40 and Debian 13. Wayland and X11 both work.

What does it cost?

Nothing. SSMConnect is released under the Apache License 2.0. If it helps you, you can optionally support the project through GitHub Sponsors.

Can I copy files from one AWS server to another when port 22 is closed?

Yes. In SSMConnect for Windows, open Servers, then File transfer. Pick a server in each pane, select files or folders and press Copy. The data goes through the Systems Manager tunnels and your PC, so neither server needs an open port or a network path to the other.

Does SSMConnect file transfer need S3 or an extra server?

No. There is no bucket, no instance role change and no bastion host. The file streams through your PC in small blocks and is not saved to its disk.

Try it on a test server first

The Windows app is an early release and the Linux app is at version 1.0, so start with a non-production server either way. It takes a few minutes to install and sign in. If something is confusing, tell me and I will make it clearer.
