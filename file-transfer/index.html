Home / Documentation / Copy files between servers
Extra feature · included in SSMConnect for Windows

Copy files between AWS servers. Port 22 stays closed.

Once your servers are connected, you can also move files between them. Two panes and a Copy button: pick a server on each side, select files or folders and press Copy. No S3 bucket, no scp commands, no bastion host, and the servers never need to reach each other.

New to SSMConnect? Start with connecting to your first server; this feature uses the same connections.

Copy a file in four steps

  1. Pick the organization

    Choose your company sign-in. Both sides list only its servers.

  2. Pick two servers

    One on the left, one on the right. SSMConnect signs in with each server's saved key. Nothing to type.

  3. Select

    Open folders, then select files or whole folders on either side.

  4. Press Copy

    Copy ▶ or ◀ Copy. Watch the progress bar, or press Stop.

How the data travels

Every server already has a Systems Manager tunnel to your PC. The file window uses two of them at once.

Server A→SSM tunnel→Your PC→SSM tunnel→Server B

What that means for you

  • No inbound port is opened on either server
  • No network path is needed between the servers
  • Files stream through memory and are never saved to your disk
  • Protected by SSH between your PC and each server

Built-in care

  • Nothing connects until you pick a server
  • You confirm before anything is replaced
  • root is refused; Switch user uses sudo
  • Stop at any time; copied files stay put

Good to know

  • Linux servers over SSH. Windows servers use Remote Desktop.
  • Both servers must show Connected on the dashboard, and belong to one sign-in organization.
  • The server's key must be a .pem without a passphrase.
  • Speed depends on your PC's connection to AWS. For hundreds of gigabytes, use S3.
  • No resume: an interrupted file is copied again from the start.

Questions people ask

How do I copy files between two EC2 instances without SSH?

Use SSMConnect for Windows: open Servers, then File transfer, pick a server in each pane and press Copy. It moves the files through AWS Systems Manager tunnels, so port 22 can stay closed on both servers.

Do the two servers need to reach each other?

No. Each server is reached from your PC through its own Systems Manager tunnel. They can be in different VPCs, subnets or AWS accounts, as long as both belong to the same sign-in organization.

Is a copy of my file saved on my PC?

No. Files are read from one server and written to the other in small blocks that pass through memory. Nothing is saved to your disk.

Can I copy files owned by another user, such as a web server account?

Yes. Pick the user and click Switch user. SSMConnect stays signed in as the default user and works through sudo. The window never works as root.

How big a file can I copy?

There is no fixed limit in the app, but the data passes through your PC, so speed depends on your connection to AWS. For hundreds of gigabytes or scheduled jobs, use S3 or a same-region copy job. There is no resume: an interrupted file starts again.

Does it work for Windows servers or on Linux desktops?

The two-pane window is in SSMConnect for Windows and copies between Linux servers over SSH. Windows servers use Remote Desktop. The Linux desktop app opens each server in your file manager over SFTP.

Try it on a test server first

SSMConnect for Windows is an early release, so start with a non-production server. Install it, add your AWS account in the wizard, and the file window is under the Servers menu.
